# Artemis.Engine.Render

Group `5_Engine` - static library inside the game process - hooks the game's render and window input for the dev tools.

## Responsibility
Finds the swap chain methods without touching the game's one (`SwapChainLocator`), hooks `Present` and `ResizeBuffers` to give the
development tools a frame to draw on (device, context, render target), hooks the three HUD passes of the game (`ChudDetour`, VW.6.x), and hooks the window procedure and `GetRawInputData` to
dispatch window messages and raw mouse movement to registered handlers (`InputService`).

HUD passes of the game (VW.6.x): `ChudDetour` hooks `chud draw` (0x2c29f8), `chud draw late` (0x2c2628) and `chud draw 3D` (0x2c279c), the game's HUD passes inside the render of a view, all `void(uint32 user)`. Each is found with `AOBService::FindFunctionAtRva` by its RVA and the exact start of its prologue (`k_ChudDrawRva` / `k_ChudDrawPrologue` and the like in `Engine.Base.Memory.Type`, no slack: a moved function is not hooked). A prologue that does not match logs an ERROR and that one hook is not installed, the others and the Viewer keep working as before. Installed by `Mod` after Present and ResizeBuffers, removed first at shutdown (disable, `WaitForIdle`, remove).

First person (D331): `FirstPersonDetour` hooks the first person model pass (`void(void* camera, uint32 user, uint8 pass)`, 0x286ebc, the arms and weapon, which only queues the model), the pass 0x26da08 (`void(void* view, int32 pass)`, VW.6.y.2 A5, see below), the forward pass 0x26ea78 (`void(void* view, uint8 phase)`, VW.6.y.2 D, see below) and the game's first person unit test (`bool(uint32 user, uint32 objectHandle)`, 0x266104, answer in AL). Each is found with `FindFunctionAtRva` by RVA and exact prologue (`k_FirstPersonModelRva` and the like in `Engine.Base.Memory.Type`, window 0). A prologue that does not match logs an ERROR, that hook is not installed and the others still are (`RenderStore::IsFirstPersonDepthPassHooked` and `IsFirstPersonForwardHooked`, the Viewer line says `depth pass yes / no, forward yes / no`). Installed by `Mod` in `OnEngineInitialized` after `ChudDetour`, removed in `OnUnhook` and at shutdown (disable, `WaitForIdle`, remove, serialized by a mutex). The model detour returns without calling the original when the user is 0 and `RenderStore::IsFirstPersonHidden` (option `Hide first person`) is set or Drive is active. The unit test detour calls the original and, for user 0 with Drive active and an original answer of true, answers false so the game draws the player's own biped and the third person effects. Users other than 0 are never changed. Drive is active when `CameraOverrideStore::Read(k_OverrideMaxAge)` finds a pose, the same rule `ObserverCameraDetour` applies. The unit test is also called by effects and possibly from a thread other than the render: the detours do not assume a thread, read only atomics and the store without locking, do not allocate and do not log. The decisions are the pure static `IsFirstPersonModelSkipped` and `IsThirdPersonShown`. `RenderStore` counts the turned answers (`CountThirdPerson`), `EndHudFrame` at Present closes the count (`WasThirdPersonLastFrame`). For user 0 the detour also counts, with one relaxed atomic add and nothing else (no lock, no allocation, no log, any thread), every FINAL answer true, the one the game receives (`CountFirstPersonUnit`, not when Drive turned it to false), and `EndHudFrame` closes it (`WasFirstPersonUnitLastFrame`, VW.6b.1: at least one answer true for user 0 in the last closed frame, whatever the object; the game answers true for the unit of the user, or an object whose parent is it, only in first person). The original is still called first and once and `IsFirstPersonModelHooked` / `IsFirstPersonUnitHooked` say what is installed. Render only: the pose of the director is never written. `Uninstall` waits 20 ms between disabling and draining, so a thread past the jump but not yet inside its `HookScope` is counted before the trampolines are removed.

First person mask of the overlay (VW.6.y.2 B, E, D332): the game draws the arms and weapon in the first call of `0x26DA08` with pass `k_FirstPersonMaskPass` (0xB) of each frame or, when a mesh of the previous frame sets a flag of its shader (a Ghost, a Revenant, the fuel rod), in the first call with pass `k_FirstPersonZeroPass` (0) after the scene, with no depth stencil bound at the entry. The overlay would cover them, so it skips the pixels those calls write. `RenderStore::SetFirstPersonMaskRequested` (set by the Viewer, atomic) asks for the mask. `HookedDepthPass` calls `RenderService::BeginMaskCopy(pass)` before the original and `EndMaskCopy` after it, with the `std::optional<MaskPairKind>` that the first returns. `MaskPairKind` has two pairs, each of two textures (before and after) in `RenderStore` (`MaskTextures`, indexed by the kind): `DepthB` (the first call with pass 0xB whose bound depth stencil has the description of the pair, the resource is kept as `SetMaskFrameDepth` until `EndHudFrame`) and `DepthZero` (the first call with pass 0 that can be copied: the bound depth stencil when there is one, else the resource kept from the pass 0xB call of the same frame, else nothing, chosen by the pure `ChooseZeroMaskSource`, so a pass 0 call with another depth stencil is left to a later call and a frame with no resource has no pair). `BeginMaskCopy` does nothing unless the mask is requested and the call runs on the thread of Present with the store ready. It takes the one copy of the frame per pair (`RenderStore::TakeMaskCopy(kind)`, closed by `EndHudFrame`), reads the resource of the depth stencil view bound at that moment and, when the textures of the pair exist and have the description of that resource, `CopyResource`s it to the before texture and keeps the resource (`SetMaskSource`) so the exit copies the same one. `EndMaskCopy` copies it to the after texture and `MarkMaskCopied(kind)`. When the textures do not exist or do not match, the pass 0xB call only notes the description of the resource (`NoteMaskDesc`, a plain struct, no reference is held) and the frame has no mask. The pass 0 pair never notes one, it takes the description of the pass 0xB pair, so another depth stencil bound in a pass 0 call cannot make the textures change. The textures are DEFAULT with the description of the depth resource (R32G8X24_TYPELESS, one sample, no multisampling) and `D3D11_BIND_SHADER_RESOURCE`, each with a shader resource view of format R32_FLOAT_X8X24_TYPELESS. They are made at Present (`RenderService::PrepareMask` / `PrepareMaskPair`, never in a detour) as the pure `RenderService::PlanMask` says: Create when the mask is requested and a description is known and no attempt was made for that description (none yet, or another size, format or samples), Release when it is not requested any more, Keep otherwise (a failed or unsupported attempt is logged once and not repeated until the description changes). They are released also in `ReleaseTargets` (so at `ResizeBuffers`) and in `Cleanup`. `FrameContext::Mask` (`MaskContext`: one `MaskPairView` per pair) is filled by `MakeContext`: valid when the copies were made in the frame in progress for the handlers of `OnBeforeHud` (`IsMaskCopied`) and, for the handlers at Present, when they were made in the last completed frame (`WasMaskCopiedLastFrame`). The size of the mask may differ from the target: the shader scales the pixel by the ratio (`RenderService::ScaleToMask`, the same arithmetic). `GpuPipeline::UpdateMask(context, mask, targetWidth, targetHeight, colorScale)` binds the views of the usable pairs only to the pixel stage (`MaskPreSlot(kind)` and `MaskPostSlot(kind)`, t0 to t3, `k_MaskSlotCount` 4, null for the unusable ones) and a 32 byte constant buffer b1 (`MaskConstants`: `DepthBSize`, `DepthZeroSize`, `TargetSize`, `ValidFlags` with a bit per usable pair, `ColorScale`) made by the pure `MakeMaskConstants` (a pair is usable when valid, with both views and a size, and the target is not 0). `ClearMask` unbinds the views after the passes. The one pixel shader `PSMain` that all the map passes use (meshes, wireframe, lines, spheres, view, the others) starts with `IsFirstPersonPixel`: it discards when any usable pair differs between its two copies at the texel of `SV_Position`. `GpuStateGuard` saves and restores pixel shader resources 0 to 3 and pixel constant buffer 1. The cost per frame is two more `CopyResource` of the depth (16.6 MB each at 1920x1080 R32G8X24) per pair. The Viewer does not use the mask for the map view (it draws its own background). Only single-sample textures are masked. The mask textures are created, used and released on the Present thread only, and `ResizeBuffers` is assumed to run on that thread too (as Present, not measured), since its release does not wait for the detour. The mask compares depth only (a first person texel that writes exactly the depth already there is not masked, not possible in practice against the reversed Z clear). If the Viewer stops refreshing the request (unhooked with it set) the copies continue until it is read again.

Draw before the HUD (VW.6.x B): `RenderService::OnBeforeHud(BeforeHudHandler)` registers a handler that `chud draw` calls BEFORE the original, so what it draws ends up under the game's HUD. The handler gets a `FrameContext` made from the render target bound in slot 0 (device, immediate context, that view, its size, the store's depth stencil) and returns whether it drew. `RenderService::OnHudDraw` (the only thing the detour calls) runs it only for user 0 when: the game HUD is not hidden, it did not already run in this Present frame, the measure says the same thread as Present, the store is ready, not resizing and not shutting down, and the bound target is the store's current back buffer, of the store's device, a texture of the size of the back buffer, and viewport 0 is the whole target, so split screen never draws before the HUD (`FindBeforeHudBlocker`, pure). Nothing escapes the HUD draw: `OnHudDraw` catches everything and counts it (`RenderStore::CountHudFailure`). The whole call is wrapped in a `GpuStateGuard` (render targets 0 to 7 with the depth stencil, viewports and scissors with the counts that were bound, predication (off meanwhile), blend, depth stencil and rasterizer states, shaders, input layout, topology, vertex and index buffers, vertex constant buffer 0, pixel shader resources 0 and 1 and pixel constant buffer 1, the slots of the overlay mask: all that the Viewer passes set, they bind no other shader resources or samplers). A handler that returns true marks the frame: `RenderStore::MarkBeforeHud` records the index of the Present frame (`NextPresentFrame` ends each Present, after the frame handlers), `IsBeforeHudMarked` tells the Present handlers that the work was done, so each one draws at Present only when it was not: exactly once per frame, never twice. A handler that throws is logged and the frame counts as handled too (status `Failed`), so Present does not draw it a second time. `BeforeHudStatus` keeps why the last completed frame did or did not draw before the HUD (no HUD draw in the frame, other thread, not ready, target of another size, game HUD hidden, handler declined).

With the atomic flag `RenderStore::IsGameHudHidden` (set by the Viewer option `Hide game HUD`) the three detours return without calling the original. Otherwise they call it untouched. `chud draw` also measures, for user 0 only: the number of calls between two Present (`CountHudCall` / `EndHudFrame`, `HudHookInfo::CallsPerFrame`) and, only when it runs on the thread of Present (`RenderStore::GetPresentThread`, noted at each Present), the render target bound in slot 0 (size, format, whether it is the back buffer) and viewport 0, read with `OMGetRenderTargets` and `RSGetViewports` on the immediate context. On another thread nothing of D3D is touched and the sample only says "other thread". It also reads the depth stencil view bound in the same call (`OMGetRenderTargets` with a view out, `HudHookInfo::Depth`: size, texture and view format, flags, resource address as an integer). The sample is copied into the store under a short lock (`SetHudSample`, `GetHudHook`). No allocation, no D3D call other than those reads.

## Does not
- Draw anything itself: `DevTools.Gui` and `DevTools.Viewer` draw.
- Affect the tick: it can be left uninstalled and the pipeline runs the same.

## Input and output
- Input: the game's swap chain and window messages.
- Output: frame callbacks (`FrameContext`) and input callbacks for the handlers.

## Public interface
Other projects may import only these modules; everything else in the project is internal.

| Module | What it gives |
|---|---|
| `Engine.Render.Layer` | The facade: store, services, locator and detours. Owner only. |
| `Engine.Render.Type`, `Engine.Render.State`, `Engine.Render.System`, `Engine.Render.Hook` | Frame types and handlers, `RenderStore` (D3D11 objects, render flags, the `HideGameHud` flag and the `HudHookInfo` measure), the HUD detours (`ChudDetour`), `RenderService`, the present and resize detours, and the `GpuPipeline` of the debug passes with its `SurfaceMode` (opaque, overlay, translucent, depth only with the color write mask at 0 and a depth bias away from the camera, wireframe with no bias and no depth write; D325). The depth is reversed (near 1, far 0, test greater or equal; the caller clears it to 0). |
| `Engine.Render.Window.Type`, `Engine.Render.Window.System`, `Engine.Render.Window.Hook` | Window messages, raw mouse, `InputService` and the window detours. |

## Depends on
`Common`, `Services`, `Engine.Base`.

## State between ticks
The D3D11 objects bound to the game's swap chain and the render flags.

## Threads
The render thread of MCC for the frame hooks (the HUD passes run on the thread that renders the view, which the measure compares with the thread of Present); the window thread for messages. Flags and sizes are atomic; D3D11 objects are touched
only from the render thread. `WaitForIdle` waits for the hooks in flight before unhooking.

## Errors
If it cannot hook, the tools do not appear and everything else runs.

## Requirements
Can be disabled entirely without changing the tick.

## Tests
`EngineLayerTests` builds it without the game; the rest is manual (the user sees the UI).

Overlay in the scene (VW.6.z, D333, moved by VW.6.z.1, D334): `HookedOpaque` (hook of the opaque color pass 0x26E500, `void(void* view)`, once per view, which draws the color of the opaque world; the entry of 0x26EA78 phase 0 was under the world) calls the original and AFTER it `RenderService::OnSceneDraw`, so the passes of the overlay are drawn inside the frame of the game, in the HDR target, over the opaque world and before its transparents, effects, blade, shields and HUD, which compose over them against the depth of the game (the overlay keeps its own depth, D325). `OnSceneDraw` runs the same handlers as `OnHudDraw` (`OnBeforeHud`, shared `RunBeforeHudHandlers` inside a `GpuStateGuard`; one registration) when: `RenderStore::IsOverlayInSceneRequested` (set by the Viewer), the frame is not marked, `FindSceneBlocker` (pure, same checks as `FindBeforeHudBlocker` through one helper) finds nothing: store ready, not resizing nor shutting down, a texture bound in slot 0 of the device of the store, of the size of the back buffer, ONE sample (`BeforeHudStatus::Multisampled`) and viewport 0 covering it, so split screen never draws in the scene, and then it is the first such call of the Present frame (`RenderStore::TakeSceneCall`, taken only after the blocker passes, so a blocked call of another view does not use the point up). The target need not be the back buffer (it is the HDR target, R11G11B10_FLOAT measured; any format that can be an RTV). `FrameContext` has the bound RTV and its size, the depth stencil of the store and the mask of the frame in progress. The format and size are logged once (`INFO: The overlay draws in the scene, target format ...`). A handler that drew marks the frame (`MarkBeforeHud`), so the HUD draw and Present do not draw again; otherwise everything is as before (before the HUD, else Present). `OnSceneDraw` catches everything and counts it (`CountSceneFailure`). The game HUD hidden does not block it. Where the last completed frame was drawn: `RenderStore::GetDrawPlace` (`DrawPlace::Scene`, `Hud`, `Present`) and, when the scene option was on and the place is not the scene, why: `GetSceneStatus` (a `BeforeHudStatus`: the blocker, `Declined`, `Failed`, `NoSceneCall` when the opaque color pass was not called in the frame). The depth pairs 0xB and 0 are copied before the opaque color pass (0x26DA08 runs before it) and are used as before. The colors of the overlay go through the exposure, bloom and tone mapping of the game, and the HDR target does not hold 0..1 colors, so the scene point scales them by the slider of the Viewer only: `HandleSceneDraw` sets `FrameContext::ColorScale` (1 everywhere else) with the pure `RenderService::ComputeSceneColorScale(slider)` (a slider that is not finite or not positive counts as 1) and keeps it for the telemetry (`SetSceneColorScale`). The Viewer gives the slider with `SetSceneColorSlider` at the start of each Present frame. The scale is a float of the pixel shader constant buffer b1 (`MaskConstants::ColorScale`, `GpuPipeline::UpdateMask` takes it): `PSMain` multiplies the output RGB by it and leaves the alpha, one shader, no duplicates. The HUD and Present draws use `ColorScale` 1.
