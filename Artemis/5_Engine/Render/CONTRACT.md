# Artemis.Engine.Render

Group `5_Engine` - static library inside the game process - hooks the game's render and window input for the dev tools.

## Responsibility
Finds the swap chain methods without touching the game's one (`SwapChainLocator`), hooks `Present` and `ResizeBuffers` to give the
development tools a frame to draw on (device, context, render target), hooks the three HUD passes of the game (`ChudDetour`, VW.6.x), and hooks the window procedure and `GetRawInputData` to
dispatch window messages and raw mouse movement to registered handlers (`InputService`).

HUD passes of the game (VW.6.x): `ChudDetour` hooks `chud draw` (0x2c29f8), `chud draw late` (0x2c2628) and `chud draw 3D` (0x2c279c), the game's HUD passes inside the render of a view, all `void(uint32 user)`. Each is found with `AOBService::FindFunctionAtRva` by its RVA and the exact start of its prologue (`k_ChudDrawRva` / `k_ChudDrawPrologue` and the like in `Engine.Base.Memory.Type`, no slack: a moved function is not hooked). A prologue that does not match logs an ERROR and that one hook is not installed, the others and the Viewer keep working as before. Installed by `Mod` after Present and ResizeBuffers, removed first at shutdown (disable, `WaitForIdle`, remove).

First person (D331): `FirstPersonDetour` hooks the first person model pass (`void(void* camera, uint32 user, uint8 pass)`, 0x286ebc, the arms and weapon, which only queues the model), the pass 0x26da08 (`void(void* view, int32 pass)`, VW.6.y.2 A5, see below), the forward pass 0x26ea78 (`void(void* view, uint8 phase)`, VW.6.y.2 D, see below) and the game's first person unit test (`bool(uint32 user, uint32 objectHandle)`, 0x266104, answer in AL). Each is found with `FindFunctionAtRva` by RVA and exact prologue (`k_FirstPersonModelRva` and the like in `Engine.Base.Memory.Type`, window 0). A prologue that does not match logs an ERROR, that hook is not installed and the others still are (`RenderStore::IsFirstPersonDepthPassHooked` and `IsFirstPersonForwardHooked`, the Viewer line says `depth pass yes / no, forward yes / no`). Installed by `Mod` in `OnEngineInitialized` after `ChudDetour`, removed in `OnUnhook` and at shutdown (disable, `WaitForIdle`, remove, serialized by a mutex). The model detour returns without calling the original when the user is 0 and `RenderStore::IsFirstPersonHidden` (option `Hide first person`) is set or Drive is active. The unit test detour calls the original and, for user 0 with Drive active and an original answer of true, answers false so the game draws the player's own biped and the third person effects. Users other than 0 are never changed. Drive is active when `CameraOverrideStore::Read(k_OverrideMaxAge)` finds a pose, the same rule `ObserverCameraDetour` applies. The unit test is also called by effects and possibly from a thread other than the render: the detours do not assume a thread, read only atomics and the store without locking, do not allocate and do not log. The decisions are the pure static `IsFirstPersonModelSkipped` and `IsThirdPersonShown`. `RenderStore` counts the turned answers (`CountThirdPerson`), `EndHudFrame` at Present closes the count (`WasThirdPersonLastFrame`). For user 0 the detour also counts, with one relaxed atomic add and nothing else (no lock, no allocation, no log, any thread), every FINAL answer true, the one the game receives (`CountFirstPersonUnit`, not when Drive turned it to false), and `EndHudFrame` closes it (`WasFirstPersonUnitLastFrame`, VW.6b.1: at least one answer true for user 0 in the last closed frame, whatever the object; the game answers true for the unit of the user, or an object whose parent is it, only in first person). The original is still called first and once and `IsFirstPersonModelHooked` / `IsFirstPersonUnitHooked` say what is installed. Render only: the pose of the director is never written. First person measurement (VW.6.y.2, measures only, the drawing does not change): the model detour, for user 0 and before the original, takes `_ReturnAddress()`, turns it into an RVA of `haloreach.dll` (the base is stored at `Install`, the address of a hooked function minus its RVA) and classifies it with the pure `FirstPersonDetour::ClassifyCaller` by function range (`k_FirstPersonCallerRanges` in `Engine.Render.Type`: 0x26DA08 / 498, 0x26E2A0 / 605, 0x26EA78 / 788, 0x277D00 / 543, any other is `Other` with the raw RVA). Each call is counted per caller in `RenderStore` (`CountFirstPersonCall`, closed by `EndHudFrame`). Only while a probe is armed (`RequestFirstPersonProbe` sets it, `StepFirstPersonProbe` at Present arms it at the next frame so that frame is measured whole) `RenderService::MeasureFirstPerson` reads, on the thread of Present only (another thread: the sample says "other thread" and no D3D is touched), `OMGetRenderTargets(8)` (non null count, render target 0: size, texture and view format, back buffer), the depth stencil view (size, texture and view format, view flags, resource address kept as an integer to compare), viewport 0 (with MinDepth and MaxDepth), `OMGetDepthStencilState` and `RSGetState` (a null state is the default state), releases everything and copies one `FirstPersonSample` per caller under a short lock (`SetFirstPersonSample`, 5 slots). No allocation and no log in the detour. At the Present that closes the first armed frame with first person calls, `RenderService` writes one `[FirstPersonProbe] INFO:` line per caller with calls and the HUD draw line (which also says whether its depth stencil resource is the one of 0x26EA78, compared as integers, never dereferenced) and the probe ends. The two detours read Drive each on its own, maybe on two threads, so on the frame Drive starts or ends (or when a read meets the writer, or a pose ages past 100 ms) the arms and the body may disagree for one frame: accepted. Stencil of the game (VW.6.y.2 A2, measures only): while the probe is armed `MeasureFirstPerson` keeps one reference (`RenderStore::CaptureFirstPersonDepth`, AddRef, the first one seen from the caller 0x26DA08) to the resource of the depth stencil view of the model draw. That reference is touched on the thread of Present only (the detour that captures it runs there, the others do not touch D3D) and is released (`ReleaseFirstPersonDepth`) when the probe ends, when a new probe is armed, in `ReleaseTargets` (so at `ResizeBuffers`) and in `Cleanup` at shutdown. At the first call of the model from the forward phase of the view (0x26EA78, after the G-buffer passes and before the post; its depth stencil is bound read only and a copy only reads it; at the HUD draw the stencil no longer holds the model, measured) of the armed frame on the thread of Present, `RenderService::ReadFirstPersonStencil` makes a STAGING copy texture of the same description (no bind or misc flags, CPU read), `CopyResource`, `Map(READ)` and reduces the R32G8X24 texels (depth float in bytes 0..3, stencil in byte 4, `RowPitch` respected) with the pure `RenderService::ReduceStencil` into a fixed `StencilProbeInfo` (regions all, weapon = lower right quadrant, center = box of 10% in the middle, top = upper quarter: texels, 256 stencil counters, texels per bit, depth min and max, texels at depth 0), kept with `SetStencilProbe`. This blocks the render thread until the GPU finishes the copy, once, for the one probe frame, at the request of the user; a failed step is kept as status and HRESULT and the probe goes on. `ReportFirstPersonProbe` logs one `stencil <region>` line per region with the state of Hide first person and Drive (`SetFirstPersonDriveActive`, noted by the model detour while armed). Nothing is drawn or changed. Depth pairs of the probe (VW.6.y.2 A3 to A5, measures only; A3 measured around the model call 0x286ebc, which only queues the model, and that path was removed. A4 measured the G-buffer pass 0x26E2A0, which does not change the depth, and its hook was removed in B). The pass the pairs are made around is 0x26DA08, hooked by `HookedDepthPass` (below). Its detour only reads atomics and calls the original unless a probe is armed or the mask is requested. Once the probe is armed and the depth resource is known (frame 1), `RenderService::PrepareDepthPairs` at the next Present makes up to 8 DEFAULT textures with the description of that resource (BindFlags 0, `k_DepthPairCount` pairs of before and after) and one STAGING texture, kept in `RenderStore` (`GetDepthPairs()`, a `CopyPairs`: copies, staging, description, setup, notes and the resource of each call, one class for the depth and the color pairs), and the probe closes only after the following frame (frame 2), the one that fills them. If the creation fails the status and HRESULT are kept (`CopyPairs::SetSetup`) and the probe closes with a line that says it. In frame 2 the pass detour, only on the thread of Present with the copies ready, calls `BeginDepthPair` at the entry (`OMGetRenderTargets` for the depth stencil view only, `CopyResource` of its resource to the before texture, the call noted in call order) and `EndDepthPair` at the exit (`CopyResource` of the same resource to the after texture). If no depth stencil is bound at the entry, the resource captured from the model draw (A2) is copied instead and the note says so. With Hide first person or Drive the pass still runs and the mask is empty (0 texels changed). A resource that is not a texture of the same description is noted as mismatch. The detour allocates nothing, logs nothing and touches D3D on the thread of Present only. The cost is one frame: at the Present that closes the probe `ReadDepthPairs` copies each texture to the staging one at a time, `Map`s it (blocks until the GPU finishes), copies the rows to a CPU buffer (allocation allowed there) and compares with the pure `RenderService::CompareTexels` (`CompareDepth` is its call with the depth layout `k_DepthTexelLayout`: 8 bytes per texel, 4 compared; changed texels by the 4 bytes of the float, their box, the depth range of the later copy, how many are in the weapon region, how many in the right half of the screen, the rest being the left half). `ReportDepthPairs` logs `depth call k caller 26DA08 pass <p> changed n box x0,y0..x1,y1 depth a..b weapon w right r left l` per pair and `depth between k and k+1 changed n` (texels that differ between the after of one call and the before of the next, 0 when nothing drew depth in between), then releases the copies (also when a probe is armed, in `ReleaseTargets` and in `Cleanup`). Depth of the pass 0x26DA08 (VW.6.y.2 A5, measures only): `k_FirstPersonDepthPassRva` 0x26DA08 (`k_FirstPersonDepthPassPrologue`, window 0, `void(void* view, int32 pass)`, called with 0xB by 0x26C6DC and with 0 twice by 0x26D740) queues the model, sets the first person camera, draws the list, restores the normal camera and pops. Its detour (`HookedDepthPass`) calls `BeginDepthPair(Pass1, pass)` at the entry and `EndDepthPair` at the exit. `k_DepthPairCount` is 6 (0x26DA08 three times per frame, with margin). The pair copy (`BeginPairCopy`, `EndPairCopy`, `CreateCopyPairs`, `CopyTextureToCpu` in `RenderService.cpp`) is shared by the depth and the color pairs. A `DepthPairNote` keeps the caller and the pass argument, and the log line is `depth call k caller 26DA08 pass <p> changed ...`. A hook whose prologue does not match logs an ERROR and the others go on (the Viewer line says `depth pass yes / no`). `Uninstall` waits 20 ms between disabling and draining, so a thread past the jump but not yet inside its `HookScope` is counted before the trampolines are removed.

Color of the forward pass 0x26EA78 (VW.6.y.2 D, measures only, it decides whether the first person parts that the depth pass 0xB does not cover are drawn there): `k_FirstPersonForwardRva` 0x26EA78 and `k_FirstPersonForwardPrologue` (`Engine.Base.Memory.Type`, window 0, `void(void* view, uint8 phase)`, the phase is a char in DL) are hooked by `FirstPersonDetour::HookedForward`, installed like the depth pass (an ERROR if the prologue does not match, the others go on) and removed with the others. `HookedForward` calls `RenderService::BeginColorPair(phase)` before the original and `EndColorPair` after it, inside a `HookScope`. Without a probe armed it only reads atomics and calls the original, it never allocates or logs and touches D3D on the thread of Present only. Frame 1 of the probe (the one that measures the callers): the first call with a render target 0 bound notes its description (`RenderStore::NoteColorDesc`, a plain struct, no reference held, like `NoteMaskDepthDesc`). At the next Present `PrepareColorPairs` makes `k_ColorPairCount` (4) pairs, 2 * 4 DEFAULT textures with that description (BindFlags 0, MiscFlags 0) and one STAGING, in `RenderStore::GetColorPairs()` (the same `CopyPairs` as the depth pairs). Only the first 4 calls of the frame are measured, and a call whose target 0 does not have the description of the first one is `Mismatch` (the log line names the format and size kept). A target of more than one sample or of a format that is not 4 bytes per texel (R11G11B10_FLOAT, R10G10B10A2, 8 bit RGBA or BGRA) is kept as unsupported. `StepFirstPersonProbe` waits for that attempt like for the depth pairs. If no description was noted the setup state says so and the probe closes with `color pairs: none (...)`. Frame 2: `BeginColorPair` copies the resource of the render target 0 to the before texture (`ColorPairNote` with `PairState::Copied` and the phase), noting `NoTarget` when no target is bound and `Mismatch` when its description differs from the copies, and `EndColorPair` copies the same resource to the after texture. At the Present that closes the probe `ReadColorPairs` reads each pair through the staging and compares them with `CompareTexels` and the color layout `k_ColorTexelLayout` (4 bytes per texel, 4 compared, no depth range, 0 in the range fields). Intersection: `ReadDepthPairs` keeps the `ChangedMap` (a byte per texel) of the FIRST depth pair with pass 0xB that was copied and read, and `ReadColorPairs` gives each color pair the pure `RenderService::CountOutsideMask(depthMask, colorMap)`: the color texels that changed and are not changed in that depth pair, the same frame. When the sizes of the two maps differ, or there is no depth pair 0xB, there is no count (the line says `n/a (size differs)` or `n/a (no depth pair 0xB read)`) and no scaling is made. Allocation and the blocking read happen only at Present. `ReportCopyPairs` (called where the depth pairs were reported) logs the depth lines and then, per color pair, `[FirstPersonProbe] INFO: color call k caller 26EA78 phase <p> copied changed n box x0,y0..x1,y1 weapon w right r left l outside depth mask o (<format> WxH)`, or `... not copied (no render target 0 bound)` / `(the render target 0 is not the texture of the copies)` / `not read: ...`, or the single line `color pairs: none (reason)`. The copies are released as the depth ones (end of the probe, new probe, `ReleaseTargets`, `Cleanup`). Nothing that is drawn changes. Reading of the result: with Hide first person off, `outside depth mask` large and inside `weapon` for a weapon whose parts the depth mask misses says that the forward pass draws them (H3), and with Hide first person on the forward phase 0 should change about nothing.

First person mask of the overlay (VW.6.y.2 B, D332): the game draws the arms and weapon in the first call of `0x26DA08` with pass `k_FirstPersonMaskPass` (0xB) of each frame (measured in A5: about 223594 texels at the lower right, none with Hide first person), before the post and the HUD, so the overlay drawn before the HUD would cover them. `RenderStore::SetFirstPersonMaskRequested` (set by the Viewer, atomic) asks for the mask. `HookedDepthPass` calls `RenderService::BeginMaskCopy(pass)` before the original and `EndMaskCopy` after it. `BeginMaskCopy` does nothing unless the pass is 0xB, the mask is requested and the call runs on the thread of Present with the store ready. It takes the one copy of the frame (`RenderStore::TakeMaskCopy`, closed by `EndHudFrame`, so only the first call with 0xB counts), reads the resource of the depth stencil view bound at that moment (the same helper as `BeginDepthPair`, one copy function for the two uses) and, when the mask textures exist and have the description of that resource, `CopyResource`s it to the before texture and keeps the resource (`SetMaskSource`) so the exit copies the same one. `EndMaskCopy` copies it to the after texture and `MarkMaskCopied`. With no depth stencil bound the frame has no mask. When the textures do not exist or do not match, `BeginMaskCopy` only notes the description of the resource (`NoteMaskDepthDesc`, a plain struct, no reference is held) and the frame has no mask. The two textures are DEFAULT with the description of the depth resource (R32G8X24_TYPELESS, one sample, no multisampling) and `D3D11_BIND_SHADER_RESOURCE`, each with a shader resource view of format R32_FLOAT_X8X24_TYPELESS. They are made at Present (`RenderService::PrepareMask`, never in a detour) as the pure `RenderService::PlanMask` says: Create when the mask is requested and a description is known and no attempt was made for that description (none yet, or another size, format or samples), Release when it is not requested any more, Keep otherwise (a failed or unsupported attempt is logged once and not repeated until the description changes). They are released also in `ReleaseTargets` (so at `ResizeBuffers`) and in `Cleanup`. `FrameContext::Mask` (`MaskContext`: the two views, their size and `IsValid`) is filled by `MakeContext`: valid when the copies were made in the frame in progress for the handlers of `OnBeforeHud` (`IsMaskCopied`) and, for the handlers at Present, when they were made in the last completed frame (`WasMaskCopiedLastFrame`, the textures still hold it, so the fallback drawing at Present can use it too). The size of the mask may differ from the target: the shader scales the pixel by the ratio (`RenderService::ScaleToMask`, the same arithmetic). `GpuPipeline::UpdateMask(context, mask, targetWidth, targetHeight)` binds the views to the pixel stage (`k_MaskPreSlot` 0, `k_MaskPostSlot` 1) and a 32 byte constant buffer (`k_MaskBufferSlot` 1: sizes and `MaskOn`) and `ClearMask` unbinds the views after the passes. The one pixel shader `PSMain` that all the map passes use (meshes, wireframe, lines, spheres, view, the others) starts with `IsFirstPersonPixel`: with the mask on and the two depths different at the texel of `SV_Position`, it discards. `GpuStateGuard` saves and restores pixel shader resources 0 and 1 and pixel constant buffer 1. Nothing else of the frame changes. The Viewer does not use the mask for the map view (it draws its own background). Diagnosis (VW.6.y.2 C): `GpuPipeline::UpdateMask(context, mask, isMaskShown, targetWidth, targetHeight)` takes a debug bool. `MaskConstants` stays 32 bytes (the first uint of the old padding is now `MaskShown`, the cbuffer is `uint MaskOn; uint MaskShown; uint2 MaskPadding`). With a valid mask and `isMaskShown`, `PSMain` returns opaque red `float4(1, 0, 0, 1)` on the mask pixels instead of `discard` (the derivatives are computed before, so the early return is not inside divergent flow). With it off the shader skips exactly the same pixels as before. Telemetry of the mask: `BeginMaskCopy` counts every call with pass 0xB and the mask requested (`RenderStore::CountMaskPassCall`, atomic, before any check that can leave without copying, so the detour does not change). `EndHudFrame`, only with the mask requested, feeds the pure `Engine::Render::Type::AdvanceMaskWindow` with whether the frame copied and its 0xB calls: every `k_MaskWindowFrames` (120) frames it publishes frames, frames without copy and the most 0xB calls of one frame (`RenderStore::GetMaskWindowReport`, empty before the first window and when the mask is not requested, which also resets the window in progress).

Draw before the HUD (VW.6.x B): `RenderService::OnBeforeHud(BeforeHudHandler)` registers a handler that `chud draw` calls BEFORE the original, so what it draws ends up under the game's HUD. The handler gets a `FrameContext` made from the render target bound in slot 0 (device, immediate context, that view, its size, the store's depth stencil) and returns whether it drew. `RenderService::OnHudDraw` (the only thing the detour calls) runs it only for user 0 when: the game HUD is not hidden, it did not already run in this Present frame, the measure says the same thread as Present, the store is ready, not resizing and not shutting down, and the bound target is the store's current back buffer, of the store's device, a texture of the size of the back buffer, and viewport 0 is the whole target, so split screen never draws before the HUD (`FindBeforeHudBlocker`, pure). Nothing escapes the HUD draw: `OnHudDraw` catches everything and counts it (`RenderStore::CountHudFailure`). The whole call is wrapped in a `GpuStateGuard` (render targets 0 to 7 with the depth stencil, viewports and scissors with the counts that were bound, predication (off meanwhile), blend, depth stencil and rasterizer states, shaders, input layout, topology, vertex and index buffers, vertex constant buffer 0, pixel shader resources 0 and 1 and pixel constant buffer 1, the slots of the overlay mask: all that the Viewer passes set, they bind no other shader resources or samplers). A handler that returns true marks the frame: `RenderStore::MarkBeforeHud` records the index of the Present frame (`NextPresentFrame` ends each Present, after the frame handlers), `IsBeforeHudMarked` tells the Present handlers that the work was done, so each one draws at Present only when it was not: exactly once per frame, never twice. A handler that throws is logged and the frame counts as handled too (status `Failed`), so Present does not draw it a second time. `BeforeHudStatus` keeps why the last completed frame did or did not draw before the HUD (no HUD draw in the frame, other thread, not ready, target of another size, game HUD hidden, handler declined).

With the atomic flag `RenderStore::IsGameHudHidden` (set by the Viewer option `Hide game HUD`) the three detours return without calling the original. Otherwise they call it untouched. `chud draw` also measures, for user 0 only: the number of calls between two Present (`CountHudCall` / `EndHudFrame`, `HudHookInfo::CallsPerFrame`) and, only when it runs on the thread of Present (`RenderStore::GetPresentThread`, noted at each Present), the render target bound in slot 0 (size, format, whether it is the back buffer) and viewport 0, read with `OMGetRenderTargets` and `RSGetViewports` on the immediate context. On another thread nothing of D3D is touched and the sample only says "other thread". It also reads the depth stencil view bound in the same call (`OMGetRenderTargets` with a view out, `HudHookInfo::Depth`: size, texture and view format, flags, resource address as an integer). The sample is copied into the store under a short lock (`SetHudSample`, `GetHudHook`). No allocation, no D3D call other than those reads.

## Does not
- Draw anything itself: `DevTools.Gui` and `DevTools.Viewer` draw.
- Affect the tick: it can be left uninstalled and the pipeline runs the same.

## Input and output
- Input: the game's swap chain and window messages.
- Output: frame callbacks (`FrameContext`) and input callbacks for the handlers.

## Public interface
Other projects may import only these modules; everything else in the project is internal.

| Module | What it gives |
|---|---|
| `Engine.Render.Layer` | The facade: store, services, locator and detours. Owner only. |
| `Engine.Render.Type`, `Engine.Render.State`, `Engine.Render.System`, `Engine.Render.Hook` | Frame types and handlers, `RenderStore` (D3D11 objects, render flags, the `HideGameHud` flag and the `HudHookInfo` measure), the HUD detours (`ChudDetour`), `RenderService`, the present and resize detours, and the `GpuPipeline` of the debug passes with its `SurfaceMode` (opaque, overlay, translucent, depth only with the color write mask at 0 and a depth bias away from the camera, wireframe with no bias and no depth write; D325). The depth is reversed (near 1, far 0, test greater or equal; the caller clears it to 0). |
| `Engine.Render.Window.Type`, `Engine.Render.Window.System`, `Engine.Render.Window.Hook` | Window messages, raw mouse, `InputService` and the window detours. |

## Depends on
`Common`, `Services`, `Engine.Base`.

## State between ticks
The D3D11 objects bound to the game's swap chain and the render flags.

## Threads
The render thread of MCC for the frame hooks (the HUD passes run on the thread that renders the view, which the measure compares with the thread of Present); the window thread for messages. Flags and sizes are atomic; D3D11 objects are touched
only from the render thread. `WaitForIdle` waits for the hooks in flight before unhooking.

## Errors
If it cannot hook, the tools do not appear and everything else runs.

## Requirements
Can be disabled entirely without changing the tick.

## Tests
`EngineLayerTests` builds it without the game; the rest is manual (the user sees the UI).

Mask threading assumption (VW.6.y.2 B review): the mask textures are created, used and released on the Present thread only; `ResizeBuffers` is assumed to run on that thread too (as Present, not measured), since its release does not wait for the detour. Only single-sample depth of the description noted at the first copy is masked; the mask compares depth only (a first person texel that writes exactly the depth already there is not masked, not possible in practice against the reversed Z clear). If the Viewer stops refreshing the request (unhooked with the flag on) the copies continue until the option is read again.
